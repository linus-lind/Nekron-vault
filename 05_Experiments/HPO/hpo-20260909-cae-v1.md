## 1. Pre-registration

**Selection set**
Ordinary rolling cross validation. Inside a fold, the model is fitted on `train` and `val` chooses the epoch to stop at. The fold's `test` window is then scored and **the pooled held-out R-squared across every fold is what one configuration is compared with another on**.

`train.selection_metric: total_r2` and the campaign metric `test_total_r2` are the same *statistic* on two different windows, which is the point — early stopping and configuration selection must optimize the same quantity, measured where each belongs. Switching the campaign to `test_predictive_r2` therefore also means switching `train.selection_metric` to `predictive_r2`, and starting a new generation.

**Frozen constants**

## 3. Metrics
### Decides

| Metric               | Role      | Rule                                                                                                                    |
| -------------------- | --------- | ----------------------------------------------------------------------------------------------------------------------- |
| `test_total_r2`      | primary   | the only metric that can accept a trial. Higher is better.                                                              |
| `test_predictive_r2` | guardrail | can only reject, never accept. A candidate that wins on the primary but drops this by more than its band is `rejected`. |
### Informs

Never enters a decision. Recorded so a result can be explained afterwards.

| Metric | Read for |
|---|---|
| `val_total_r2`, pooled | early stopping's own optimism. `val - test` **widening** when a coordinate moves means the new configuration bought its score from the epoch choice, not from the model |
| `fold/gap_total_r2` | in-sample minus inner-holdout fit at the selected epoch. Its movement, never its level — `train/total_r2` accumulates while the weights move |
| `best/grad_norm_p90` | the value `train.grad_clip_norm` would be set from, if clipping is ever enabled |
| `fit/fit_seconds_total` | cost. Tie-break in the parsimony ladder, and what prices the remaining trial budget |

## 4. Hard gates

Admissibility only. A failed gate makes a trial `invalid`, not `rejected` — the run is not evidence either way and the coordinate stays open. Whether a change is *good* is §5; the guardrail lives there, not here.

**Machine-checked** — `scripts/hpo_stats.py` writes these into the trial's frontmatter:

| Gate                      | Condition                                                   |
| ------------------------- | ----------------------------------------------------------- |
| every fold ran            | `folds_failed == 0`                                         |
| no fold diverged          | `folds_diverged == 0`                                       |
| no fold ran out of budget | `folds_hit_cap == 0`                                        |
| same data                 | `data_key` equals the campaign's                            |
| same code, clean tree     | `git_commit` equals the campaign's and `git_dirty == false` |
| same schedule             | `folds_planned` equals the campaign's fold count            |
| a real change             | `config_hash` differs from the incumbent's                  |

**Per-fold** — each metric at the selected epoch, and the condition must hold on *every* fold. Values pinned from T00 are frozen once the noise run reports the baseline's.

| Gate                   | Condition                                                          |
| ---------------------- | ------------------------------------------------------------------ |
| something was learned  | `fold/best_epoch >= 1`                                             |
| factors not collapsed  | `best/factors_effective >= 2` of K=6, and not materially below T00 |
| factors not duplicated | `best/factors_max_abs_corr < 0.95`                                 |
| steps sane             | `best/opt_update_ratio` within `[1e-4, 1e-2]`                      |

**Read by hand:**

- [ ] exactly one coordinate, or one declared coupled pair, moved

A capped run is re-run under a raised campaign-wide `train.epochs`, never discarded: dropping capped runs biases the search toward whatever converges fastest.

## 5. Decision rule

```
accept  iff  t_corrected >= t_hurdle
        and  delta_pooled >= the band for the seed count used
        and  test_predictive_r2 did not fall by more than its own band (§3)
        and  every hard gate passed
tie     iff  abs(delta_pooled) <= that band     -> parsimony ladder
invalid iff  any hard gate failed
reject  otherwise
```

`t_corrected` — consistency across folds. Each fold gives one paired difference `d_k` between candidate and incumbent with seeds averaged in-fold, and `t = d̄ / (s_d · √(1/K + n_test/n_train))`. The square-root term is the Nadeau-Bengio correction, since overlapping walk-forward training windows make folds dependent and `s_d/√K` too small. The hurdle `3.31` is the one-sided 5% Bonferroni level for 30 trials at `df = K−1 = 21`, so thirty comparisons against the same folds cannot yield a winner by chance. It asks whether the gain is spread across folds or carried by one.

`delta_pooled` — size against seed noise. With `P_r` a run's pooled score `1 − Σsse/Σsst` over every period of every fold, `Δ = mean_s P_cand,s − mean_s P_inc,s` must clear `t(0.95,4) · σ̂ · √(1/n_inc + 1/n_cand)`, where `σ̂` is the spread of T00's five baseline scores. The square-root term turns that single-run spread into the standard error of a difference of means, so a candidate at one seed must clear `2.335·σ̂` and at three only `1.557·σ̂`; the t quantile replaces `1.645` because `σ̂` rests on five numbers. It asks whether the gain exceeds what re-rolling the seed would produce.

**Two stages.** 
Screen at seed 42 against `screen_band_1_seed`; confirm at seeds 482, 7319, 56 against `confirm_band_3_seeds`. 

**Parsimony ladder.**
(ties): fewer parameters > fewer/narrower layers > less regularization machinery > shorter wall clock > keep incumbent.

**Coupled pairs** — moved as a 3x3 joint grid, never as two 1-D sweeps:

| Pair | Why they move together |
|---|---|
| `optim.lr` x `data.batch_periods` | a larger batch averages more gradients, so it tolerates — and needs — a larger learning rate. The good region is a diagonal ridge in the two |
| `model.num_factors` x `loss.l1_lambda` | more factors is more parameters, which needs more shrinkage. K=8 judged at a penalty tuned for K=6 looks worse than it is |
| `beta_network.hidden_dims` x `dropout` | a wider network tolerates more dropout and usually needs it |

Coordinate descent moves along one axis at a time, so it can only reach the top of a ridge that runs along an axis. On a diagonal ridge every single-axis step from a point on the ridge goes downhill in both directions, and the search stops at a point that is optimal in each coordinate separately and in neither jointly. A 3x3 grid costs nine runs against six for two sweeps and is the cheapest thing that can see the diagonal.

**Not searched:**
- `train.grad_clip_norm` — set once from the observed `best/grad_norm_p90`, not tuned.
- `loss.l1_mode` — `proximal` and `subgradient` differ in effective rate by about `1/l1_lambda`, so a coefficient is not portable between them. Changing the mode ends the campaign.
- `train.device` — recorded, not chosen. A change of device changes the kernels and therefore the numbers.

**Stopping rule:** a full pass accepts nothing, or 30 screens are spent.
